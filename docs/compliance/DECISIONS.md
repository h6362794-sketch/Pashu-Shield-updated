# Pashu-Mitra — DBIM redesign merge: recorded decisions

Companion to `docs/compliance/dbim-redesign-merge-report.md`. Every entry below
is a place where the merge had to choose between the redesign ZIP and the
existing repository, or where a value could not be verified in the build
environment. Nothing here is a silent deviation.

| ID | Decision | Why | Status |
|----|----------|-----|--------|
| D-01 | The ZIP's generated shield/horns logo kit (`logo.js`, `logo-dims.js`, `brand.html`, `assets/brand/*`, `build_logos.py`, `logo_rules.test.mjs`) is **not** merged. The owner-supplied official mark `frontend/assets/pashu-mitra-logo.png` (green veterinary cross + cow head, 1024×1024 PNG) is the single logo everywhere. | The owner explicitly rejected the generated artwork and chose the official mark. | Done |
| D-02 | The DBIM hex values in `frontend/dbim-tokens.css` (key `#0F5757`, mid `#2D8686`, light `#A6D9D9`, tint `#D9F2F2`, Linen `#EBEAEA`, Brown `#150202`, Liberty Green `#198754`, Mustard `#FFC107`, Coral `#DC3545`, Blue `#0D6EFD`, greys `#C6C6C6`/`#8E8E8E`/`#606060`) come from the scanned DBIM PDF in the redesign ZIP. | `https://dbimtoolkit.digifootprint.gov.in` is **not reachable from the build sandbox** (host allow-list), so they are **UNVERIFIED** against the live Toolkit. Owner must confirm before CQW/STQC audit. Other DBIM colour groups (Burgundy, Purple, Chrome Yellow, Cinnamon Red) are deliberately **absent** rather than guessed. | **Pending owner verification** |
| D-03 | `.btn-primary:hover` inverts to white background + key-colour text instead of lightening the fill. | The only lighter shade in the Green group, `#2D8686`, gives just 4.32:1 with white text — below WCAG 1.4.3 (4.5:1). DBIM 4.4 requires distinct enabled/hover/focus/disabled states, so hover is expressed by inversion, which stays at 7.53:1. | Done |
| D-04 | `scripts/check-images.mjs` exempts `assets/pashu-mitra-logo.png` **by exact path** from the 100 KB logo budget. | The official master artwork is 250 KB at 1024×1024 and also feeds the PWA icons (192/512). Raising the budget for *all* logos would weaken the gate; an exact-path exemption keeps every other logo, favicon and icon at 100 KB. The file is still under the 500 KB banner budget and is never distorted (`height` + `object-fit:contain`, `width:auto`). | Done |
| D-05 | `--primary` and `--pm-primary` in `frontend/style.css` map to `var(--dbim-key)`, **not** `var(--dbim-mid)`; `--primary-dark`/`--pm-primary-dark` map to `var(--dbim-brown)`. | The mechanical palette migration first mapped the legacy indigo to `--dbim-mid`, which made 13 existing rules fail the contrast gate at 4.32:1 (`.btn-primary`, `.btn-outline`, `.btn-secondary`, `.pm-search-btn`, `.role-toggle button.active`, `.lang-toggle button.active`, `.nav-item.active`, `.sync-indicator`, `.pm-chart-details summary`, `.pm-state-chip[aria-current]`). DBIM 2.3 states mid is for **non-text** use only, so all text/button-fill uses were moved to key (7.53:1 on white) and dark accents to Brown (the DBIM body-text colour). `scripts/check-contrast.mjs` now reports **94 pairs checked, 0 failures**. | Done |
| D-06 | `backend/test_compliance.py::test_67` no longer asserts the retired hex literals (`--primary:#3d4db8`, `--bg:#eef0f6`, …). It now asserts that (a) `style.css` still declares every brand token and (b) the DBIM tokens in `dbim-tokens.css` are the expected values, keeping the high-contrast-scoped check unchanged. | The test's *purpose* is "high contrast must not alter the default theme" (Exemption 4.3). Pinning legacy hex constants made it incompatible with the owner-approved palette migration; the invariant is preserved, only the constants moved to the token file. | Done |
| D-07 | The redesign's `frontend/info-pages.js` deltas (search synonym map, "Did you mean" suggestion, `pmSearchCat` category chips) are **not** merged. The repository's own `info-pages.js` (39,760 B) is kept, palette-migrated only. | The ZIP copy (44,173 B) exceeds the Drive text-extraction limit available in this environment (~24 KB) and could not be retrieved intact, so its deltas cannot be copied byte-faithfully. Merging a *guessed* re-implementation of a search feature into a working info-page module was judged riskier than leaving it out. Existing site search is unchanged and still tested. | **Deliberate omission — follow-up** |
| D-08 | `frontend/dbim-shell.js` was authored in-repo against the ZIP's published contract (nav model, disclosure attributes, consent API, ticker, footer strings, 4-language key sets) rather than copied. | Same extraction limit as D-07 for the ZIP's ~50 KB shell source. The contract is pinned by `frontend/tests/shell_official_logo.test.mjs` (13 tests), so behaviour is verified rather than assumed. | Done |
| D-09 | Noto Sans is self-hosted from the `@fontsource/noto-sans*` npm packages (SIL Open Font License 1.1) — `scripts/fetch-fonts.sh` is kept for reproducibility but the sandbox cannot reach `github.com/notofonts` raw assets. | `registry.npmjs.org` **is** reachable, so the real woff2 subsets are vendored: latin, Devanagari (Hindi **and** Marathi) and Telugu at weights 400/500/600/700 (12 files, 444 KB) with the OFL licence text alongside. No third-party font CDN is called at runtime. | Done |
| D-10 | Internal technical identifiers keep the `pashu-shield` name: `backend/app.py` `"service":"pashu-shield-backend"`, `frontend/vercel.json` project name + rewrite destination, Render service names, database/service names, repo infrastructure. | Owner instruction: rebrand **user-facing** strings only. Renaming deploy targets would break the live Render/Vercel services. | Done |
| D-11 | Browser-based rungs (Step 14 responsive/zoom/keyboard pass, Step 15 two-real-browser WebRTC) were **not executed** in this environment. | Playwright installs from npm, but the Chromium download host is not on the sandbox allow-list (`Failed to download Chrome for Testing`), so no browser exists to drive. `frontend/tests/webcall_browser.test.mjs` reports an honest **SKIP**, never a pass. Exact reproduction commands are in the merge report. | **Not run — owner action** |
